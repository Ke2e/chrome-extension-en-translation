# Chrome 翻译插件 —— 需求文档

## 1. 项目概述

### 1.1 项目背景

用户在浏览英文网站时，阅读障碍主要来自两方面：语言不通和内容结构混乱。本插件旨在解决这两个问题——自动提取英文网页的核心文章内容，借助 AI 大模型将其翻译为中文，并以清晰、友好的 Markdown 格式呈现给用户。

### 1.2 项目目标

开发一款 Chrome 浏览器扩展，能够：

- 从任意英文网页中提取主要文章内容
- 将提取的内容转换为 Markdown 格式
- 调用 AI 大模型进行翻译
- 以打字机效果的动态方式展示翻译结果
- 本地持久化存储用户最近一次的翻译结果

## 2. 功能需求

### 2.1 内容提取

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| F-01 | 用户点击插件图标后，插件应自动识别当前标签页的主要文章内容，提取标题、正文、作者（如有）、图片等核心信息 | P0 |
| F-02 | 应过滤掉导航栏、侧边栏、广告、页脚等非文章内容 | P0 |
| F-03 | 若当前页面不支持文章提取（如视频页、搜索页等），应向用户给出明确提示 | P1 |

### 2.2 Markdown 转换

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| F-04 | 将提取到的文章内容转换为 Markdown 格式 | P0 |
| F-05 | 原文中的图片应转换为 Markdown 图片格式 `![alt](src)`，保留图片的 alt 文本和 URL | P0 |
| F-06 | 原文中的链接应转换为 Markdown 链接格式 `[text](url)` | P0 |
| F-07 | 保留原文的标题层级（h1~h6）、列表、引用等基本排版结构 | P1 |

### 2.3 AI 翻译

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| F-08 | 将 Markdown 格式的原文内容调用 AI 大模型进行翻译，翻译目标语言为中文 | P0 |
| F-09 | 支持配置 AI 模型的 API Key 和 API 地址（兼容 OpenAI 格式的接口） | P0 |
| F-10 | 翻译过程中应保留原文的 Markdown 格式标记（标题、图片、链接等），不对这些标记进行翻译 | P0 |
| F-11 | 翻译请求应使用流式（Streaming）方式，以支持打字机效果 | P0 |

### 2.4 翻译结果展示

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| F-12 | 翻译结果应以打字机效果动态逐字/逐段展示，模拟 ChatGPT 的输出体验 | P0 |
| F-13 | 展示区域应支持滚动查看长文本 | P0 |
| F-14 | 展示页面应提供"复制"按钮，方便用户一键复制翻译结果 | P1 |
| F-15 | 展示页面应提供"重新翻译"按钮，允许用户重新发起翻译 | P1 |

### 2.5 输出格式

翻译结果最终输出应严格遵循以下格式：

```
# [文章标题]

> **作者**: [作者名]
> **原文链接**: [原始文章 URL]

[翻译后的正文]
```

要求：

- 文章标题使用一级标题（`#`）
- 作者和原文链接放在引用块（`>`）中，使用加粗标记
- 作者名未知时，显示为"未知"
- 翻译后的正文保留原文的 Markdown 格式（图片、链接、列表等）

### 2.6 本地持久化

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| F-16 | 使用 Chrome Storage API 在本地持久化存储最近一次翻译结果 | P0 |
| F-17 | 每次新的翻译完成后，覆盖上一次的存储结果，不保留历史记录 | P0 |
| F-18 | 用户重新打开插件弹窗时，若存在上一次的翻译结果，应优先展示 | P1 |

## 3. 非功能需求

### 3.1 性能

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| NF-01 | 内容提取过程应在 2 秒内完成 | P1 |
| NF-02 | 打字机效果的渲染不应阻塞浏览器主线程 | P0 |
| NF-03 | 插件应尽可能减少对原始网页性能的影响 | P1 |

### 3.2 可用性

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| NF-04 | 插件应提供加载状态提示，让用户知晓当前进度（提取中 → 翻译中 → 完成） | P0 |
| NF-05 | 翻译过程中应显示"取消"按钮，允许用户中断翻译 | P1 |
| NF-06 | 网络错误或 API 调用失败时，应向用户展示友好的错误提示 | P0 |

### 3.3 兼容性

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| NF-07 | 支持 Chrome 最新版本及最近两个大版本 | P1 |
| NF-08 | 插件 UI 应适配浅色/深色模式 | P2 |

## 4. 用户界面

### 4.1 插件弹窗（Popup）

插件点击后在浏览器工具栏弹出，包含以下区域：

1. **状态栏**：显示当前状态（提取中 / 翻译中 / 已完成 / 错误）
2. **内容展示区**：展示翻译结果，支持打字机效果
3. **操作按钮区**：复制、重新翻译、取消（翻译中显示）

### 4.2 设置页（Options）

提供以下配置项：

- **AI 模型 API Key**：输入框（密码模式）
- **API 地址**：输入框，默认值 `https://api.openai.com/v1`
- **模型名称**：输入框，默认值 `gpt-4o-mini`
- **系统提示词**：文本框，允许用户自定义翻译指令

## 5. 约束与限制

- 本插件仅支持 Chrome 浏览器，基于 Manifest V3 开发
- 不提供历史记录功能，仅持久化最近一次翻译结果
- 翻译质量取决于所选 AI 模型的能力，插件本身不干预翻译质量
- 用户需自行提供 AI 模型的 API Key
- 插件不处理网页中的视频、音频等多媒体内容

## 6. 术语表

| 术语 | 说明 |
|------|------|
| Manifest V3 | Chrome 扩展的最新规范版本 |
| Streaming | 流式响应，数据分块传输，无需等待完整响应 |
| 打字机效果 | 文本逐字/逐段渐进显示，模拟打字机打字过程 |
| Markdown | 一种轻量级标记语言，使用纯文本格式编写结构化文档 |
